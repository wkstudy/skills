# 数据库锁机制底层规则库

需要解释"为什么会锁 / 为什么死锁"时读。默认 InnoDB + RR(可重复读)。来源:锁机制学习笔记。

注意:下面的间隙锁 / 临键锁规则是 **RR** 下的行为;若隔离级别是 **RC(读已提交)**,基本不加间隙锁,规则不同——先确认线上隔离级别再套用。

## 1. 锁的三维分类
- **粒度**:全局锁 / 表级锁(MDL 元数据锁、IS/IX 意向锁)/ 行级锁(InnoDB 独有)。
  - 关键:**行锁必须加在索引项上**。没命中索引 → 退化扫聚簇索引 = 锁全表。
- **性质**:共享锁 S(读读兼容、读写互斥)/ 排他锁 X(写写、写读都互斥)。
- **行锁算法**:记录锁 Record `[x]` / 间隙锁 Gap `(a,b)` / 临键锁 Next-Key `(a,b]`(RR 默认)。

## 2. 行锁退化四法则（RR）
1. 默认:访问到的索引项加 Next-Key `(a,b]`。
2. 主键/唯一等值、记录存在 → 退化 Record Lock,只锁当前行。
3. 主键/唯一等值、记录不存在 → 向右第一条不满足记录的 Next-Key 退化为 Gap `(a,b)`。
4. 普通索引等值、记录存在 → 二级索引 Next-Key `(a,b]` + 向右 Gap `(b,c)`;对应主键记录加 Record。
5. **未命中索引 → 全表每行每间隙都加 X 锁 = 全表锁死。**

## 3. UPDATE 锁特性
- **绝对排他**:表级加 IX,行级全程加 X,无 S。
- **0 行匹配仍加锁**:扫过的间隙照样加 Gap X 锁。
- **强依赖索引**:条件不走索引 = 扫全表 = 并发灾难。

## 4. 经典死锁模式
- **无索引 UPDATE**:整表读写当前读全阻塞。
- **并发 Gap Lock 冲突(最常见)**:A、B 对同一不存在范围各拿 Gap(Gap 互容),随后都 INSERT(插入意向锁与对方 Gap 互斥)→ 互等 → 死锁。
- **普通索引扩锁**:加锁延伸到前后间隙,误伤非目标值的并发插入。
