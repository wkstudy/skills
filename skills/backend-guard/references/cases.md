### [2026-10-09] [DB锁] 无索引 UPDATE 会锁住整张表，并发接口全卡住
- 来源:学习(锁机制学习,vibecoding 时自己不会意识到)
- 场景:给一张表写更新接口,WHERE 用了非索引列,例如 `UPDATE orders SET status='done' WHERE user_name = ?`(表名列名为示例)。
- 现象(典型表现):本地单人测一切正常;并发 / 上量后大面积超时、`Lock wait timeout`,表面像"数据库慢",实为整表被锁。
- 根因:InnoDB 行锁只能加在索引上。WHERE 列没索引 → 退化为扫聚簇索引 → 整表每行每间隙都被加 X 锁,其他读写全阻塞。隐式类型转换(varchar 列传数字、函数包列 `DATE(t)=`、`LIKE '%x'`)会让已有索引悄悄失效,效果等同无索引。
- 对策:① WHERE 列加索引;② 优先按主键 / 唯一索引更新 `WHERE id = ?`;③ `EXPLAIN` 确认 `type` 不是 `ALL`、`key` 不是 `NULL`。
- 检测方法:写任何 UPDATE/DELETE,立刻查 WHERE 列有无索引(`SHOW INDEX FROM 表`)、有无隐式类型转换;拿不准就 `EXPLAIN` 看 type/key。
- 适用:MySQL / InnoDB,通用于所有 ORM 的 update/delete。
- 深入:见 `db-locks.md`。
